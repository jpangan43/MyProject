## 1. Create passwords.txt on the Windows lab host

On the Windows lab machine open File Explorer and go to Documents.

Right-click in the empty area → **New** → **Text Document**.

This file will hold the password list used by Hydra (in a real engagement you would use a larger wordlist).

**Figure 1** – Documents → New → Text Document

---

## 2. Write the lab password into the list

Rename the new file to `passwords.txt` (or keep the name and edit it).

Open it in Notepad and type one or more candidate passwords (one per line).

In this lab a known password ending in “2026” is used so the attack succeeds quickly.

Save the file. You may later copy it to Kali as mywordlist.txt / rockyou subset.

**Figure 2** – passwords.txt open in Notepad with a sample password

---

## 3. (Optional) Set a known password on the Windows account

If you want a controlled lab password, open Windows Settings → Accounts → Sign-in options / Change password.

Set New password / Confirm password and optionally a hint (e.g. media).

Click **Next**. Use this same password in your Hydra wordlist so a success is guaranteed for detection demos.

**Figure 3** – Windows Settings → Change your password (hint: media)

---

## 4. Log into Kali Linux

Switch to the Kali attacker VM (or machine).

At the login screen enter the Kali username (typically **kali**) and password.

Click **Log In**.

**Figure 4** – Kali login dialog → user kali → Log In

---

## 5. Create target.txt on Kali

Open a terminal on Kali.

Create (or edit) a target file that will hold the IP and username for Hydra:

```bash
sudo nano target.txt
```

**Figure 5** – Terminal: sudo nano target.txt

---

## 6. Put target IP and username in target.txt

In nano enter two lines (or the format Hydra expects for your chosen mode):

- Line 1: target IP address (e.g. 66.135.26.132)
- Line 2: username Administrator

Save (Ctrl+O, Enter) and exit (Ctrl+X).

Alternatively you can pass `-l Administrator` and the IP on the command line without a file.

**Figure 6** – nano target.txt contents: IP + Administrator

---

## 7. Run Hydra against RDP and capture valid password

Run Hydra’s experimental RDP module against the target.

Example form (adjust IP / wordlist path as needed):

```bash
hydra -l Administrator -P mywordlist.txt rdp://<TARGET-IP> -t 1 -V
```

Hydra tries each password; when it finds a valid one it prints:

`[3389][rdp] host: ... login: Administrator password: ...`

and reports “1 valid password found”.

**Figure 7** – hydra -l Administrator -P mywordlist.txt rdp://... → valid password found

---

## 8. Connect with xfreerdp using the cracked credentials

Use FreeRDP to open an interactive session with the credentials Hydra discovered:

```bash
xfreerdp /u:Administrator /p:<PASSWORD> /v:<TARGET-IP>:3389
```

**Figure 8** – xfreerdp /u:Administrator /p:... /v:...:3389

---

## 9. Successful RDP desktop session

A FreeRDP window opens displaying the remote Windows desktop.

This confirms successful initial access via RDP password spraying / brute force in the lab environment.

**Figure 9** – FreeRDP window showing the Windows desktop

## 10. Next Steps (Detection Focus)

- In Elastic / Kibana review the SSH or Windows Security / RDP logon failures generated by Hydra (Event ID 4625, etc.).
- Confirm your threshold alert for failed authentications fired (see the Alerts & Dashboards guide).
- Open an osTicket case for the “incident” and document the source IP (Kali).
- Practice containment: disable the account, block the source IP, or require MFA / account lockout policies.
- Never run Hydra (or similar tools) against production or third-party systems without written authorization.

> **Legal / ethical note**: Password guessing and unauthorized access are illegal outside of systems you own or have explicit permission to test. This guide is for isolated SOC lab training only.
